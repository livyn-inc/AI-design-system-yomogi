# /ads-setup（初期セットアップ実行）

## 概要
Yomogiの技術的セットアップと、必要に応じた短い制作ヒアリングへの導線を案内するCursor用ショートカットです。実行処理はnpm scriptsを基本にします。

## 実行前アナウンス
- これから行う処理（Node確認 → 依存インストール → build-all → Storybook案内）を説明します。
- 開始前に短い計画を提示してから進めます。
- 進行中はステップごとに状況を画面表示します。

## 手順
0. `AGENTS.md` と `SETUP.md` の要点を確認
1. 短い実行計画を提示してユーザーの了承を得る
2. Node.js バージョン確認: `node --version`（18.x 以上を推奨）
   - 不適合の場合は更新手順を案内し、中断します。
3. 依存パッケージのインストール: `npm install`
4. トークン・コンポーネント・ページ用アセットのビルド: `npm run build-all`
   - 生成物例の確認: `build/css/tokens.css`, `pages/_assets/bundle.css`, `pages/_templates/components.js`
5. Storybook の起動（任意・推奨）: `npm run storybook`
   - ブラウザで `http://localhost:6006` を案内し、表示確認を促します。
   - 匿名テレメトリやクラッシュレポートの送信確認が出た場合は、ユーザー確認のうえNOを選択します。
6. ページ制作を始める場合は、3〜5問の短いヒアリングを行います。
   - 何を作るか
   - 誰向けか
   - 何を達成するか
   - どんな印象にしたいか
   - 避けたい印象は何か

## 実行後の次アクション
- 必要なmdcだけ参照する。`AGENTS.md` の「設計品質として守るもの」を確認。
- 初期ヒアリングが必要な場合は `.cursor/rules/ads/project-config/init-flow.mdc` を参照する。方向性が曖昧なら方向性整理のSkill、作る内容の整理は制作ブリーフ化のSkillを利用。
- ヒアリング結果は導入先プロジェクト側で保存・参照。Yomogiリポジトリには導入先固有の結果ファイルを含めません。
- 補助ショートカット:
  - `/ads-check` で品質チェックを実施
  - `/ads-gen-page` でページ生成を開始
  - チェック結果と見た感想をもとに、チャットで改善案や今回直す範囲を相談

## 注意
- ファイル変更を伴う操作は、短い計画を提示してから進めます。
- 実行ログを逐次表示し、エラー時は「失敗したコマンド」「ログの位置」「復旧手順（再実行コマンド等）」を案内します。
