# Prompt Templates

DCoSの最終出力では、短い雰囲気プロンプトで終わらせない。出力タイプに応じたテンプレートを使い、生成AIが誤解しにくい密度まで構造化する。

ユーザーにテンプレート名を説明する必要はない。Agentは裏側で適切な型を選び、自然な生成用プロンプトとして出す。

## Core Fields

すべての出力タイプで、可能な限り次の要素を含める。

```text
目的:
[何を検討/生成したいのか]

対象:
[誰に向けたデザインか]

背景:
[サービス、プロダクト、ブランド、施策の前提]

避けたい方向:
[既視感、誤解される印象、過剰に出したくない表現]

目指す体験感情:
[見た人、使う人に持ってほしい感情]

デザインコンセプト:
[一文で方向性を説明する]

参照したい文脈:
[模倣ではなく、抽出したい文化/時代/媒体/表現の文脈。何を借り、何を真似しないかも書く]

色の方向性:
[色相、明度、彩度、役割、使い方]

形・構成・ビジュアル方向:
[レイアウト、形、線、面、グラフィック、写真/イラスト方針]

含めたい要素:
[必ず入れたい情報、素材、UI部品、モチーフ]

避けるもの:
[入れないもの、寄せないもの]

出力品質:
[完成物を見たときに満たしてほしい基準]
```

## Moodboard / Visual Concept Sheet

アートディレクション、世界観、ビジュアルルールを探る初回案に使う。完成画面ではなく、方向性検討用の1枚として指定する。

```text
[対象サービス/ブランド]のムードボード兼ビジュアルコンセプトシートを作成してください。

目的:
完成画面ではなく、アートディレクションとビジュアル方向性を探るための初回案を作りたいです。
世界観、色、UI部品、グラフィック表現、タイポグラフィの方向性が伝わる1枚にしてください。

サービス/ブランド概要:
[何のサービス/ブランドか]

対象ユーザー:
[誰に向けたものか]

背景:
[なぜこの方向性を検討しているか]

避けたい方向:
[避けたい既視感や誤解される印象]

目指す体験感情:
[見た瞬間に持ってほしい感情]

デザインコンセプト:
[短いコンセプトと説明]

参照したい文脈:
- [参照文脈1]から、[借りる考え方/構造/表現原理]を参考にする
- [参照文脈2]から、[借りる考え方/構造/表現原理]を参考にする
- [参照文脈3]から、[借りる考え方/構造/表現原理]を参考にする
- ただし、見た目、レイアウト、ブランド固有表現は模倣しない

色の方向性:
[色の方向と使い方]

ビジュアル方向:
[全体の雰囲気、構図、素材感、UI断片、グラフィック]

作ってほしいもの:
1枚のムードボード兼ビジュアルコンセプトシート。
完成画面ではなく、方向性検討用のアートディレクションボードです。

含めたい要素:
- 色の方向性
- タイポグラフィの雰囲気
- UI部品やレイアウト断片の雰囲気
- アイコンや図形の方向性
- 背景や装飾の方向性
- 第一印象を表すビジュアル

避けるもの:
- [避けるもの1]
- [避けるもの2]
- [避けるもの3]

出力品質:
[第一印象で何を感じたいか。後工程へ展開できる明快なルールが見えること]
```

## Choosing A Template

デフォルトでは、複数種類のプロンプトを同時に出さない。ユーザーの現在の目的に合う1種類を選ぶ。

- ムードボード、世界観、アートディレクション検討: `Moodboard / Visual Concept Sheet`
- サービスサイト、EC、LP、トップページ: `LP / Website`
- 実際のプロダクト画面: `UI Screen`
- 広告、SNS、キャンペーン、ECトップ訴求: `Banner / Campaign Visual`

出力時には、選んだ理由を短く添える。

```text
今回は「サイトの雰囲気を決めたい」が目的なので、
まずムードボード兼ビジュアルコンセプトシート用のプロンプトを作ります。
```

複数候補が有効な場合も、まず使うべき1つを選ぶ。

```text
今すぐ使うならLP用プロンプトです。
ムードボード用は、ビジュアル方向を先に検証したい場合に追加で作れます。
```

ユーザーが複数を明示的に求めた場合だけ、1つに混ぜず、出力タイプごとに別々のプロンプトを作る。
