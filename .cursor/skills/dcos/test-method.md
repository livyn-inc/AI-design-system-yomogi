# DCoS Test Method

DCoSの価値は、同じテーマを複数条件で比較して確認する。テスト時も、通常ユーザーには内部構造を説明せず、Agentが自然にファシリテーションできるかを見る。

## Compare Three Inputs

```text
A. 通常プロンプト
短い依頼文だけで、AIにデザイン方向性やビジュアルを作らせる。

B. 汎用ベストプラクティス
一般的なデザイン原則、UI原則、SaaSのベストプラクティスを添えて作らせる。

C. ファシリテーション後の方向性まとめ
DCoS対話で作った方向性案、デザインコンセプト、体験感情、やること / 避けることを渡して作らせる。
```

## Good Test Themes

Palmaとは別テーマで実施する。次の条件を満たすテーマがよい。

- 既存カテゴリの既視感が強い。
- ユーザーの感情設計が重要。
- 無難なUIに寄ると魅力が出にくい。
- ムードボード、LP、UIサンプルへ展開できる。

候補:

- 子ども向けではない、大人の学習習慣アプリ。
- クリエイター向けの請求・契約管理ツール。
- 地域の小規模店舗向けAI接客支援サービス。
- 医療従事者向けのナレッジ共有ツール。

## Evaluation Criteria

```text
1. 初回品質
最初の出力だけで、方向性として使えるか。

2. 固有性
既存カテゴリの無難な見た目から距離を取れているか。

3. 体験感情との一致
ユーザーに持ってほしい感情が視覚表現に変換されているか。

4. 修正しやすさ
どこを変えれば良くなるかを説明しやすいか。

5. 生成プロンプト接続性
生成用プロンプトや詳細ブリーフへ変換しやすいか。

6. プロンプト解像度
出力タイプに合った章立てで、生成AIが誤解しにくい密度になっているか。

7. 評価しやすさ
成果物を評価するときの観点が明確か。
```

## Post-Generation Test

初回生成後もDCoS Skillが正しく動くかを確認する。

### Test Input

生成結果を見せた上で、ユーザーがラフな感想を返す。

```text
方向性は良いと思う。
ただ、少し古く見える。
もっと今の若いユーザーが取り入れる感じがほしい。
```

### Expected Behavior

Agentはすぐに作り直さず、次の形に整理する。

```text
合っている点:
- [方向性として残すもの]

違和感:
- [ユーザーが感じたズレ]

維持する:
- [次の生成でも残す要素]

弱める:
- [出すぎた要素]

強める:
- [足りない要素]

差分プロンプト:
- [次の生成に渡す具体的な調整指示]
```

### Post-Generation Evaluation

- ユーザーの感想を先に受け取れているか。
- Agentが一方的に採点しすぎていないか。
- 違和感を視覚的に操作できる言葉へ変換できているか。
- 維持/弱める/強めるが分かれているか。
- 初回プロンプトを捨てずに差分プロンプトを作れているか。

## Iteration Test

初稿以降を反復として扱えるかを確認する。

### Test Input

```text
2回目はかなり良くなった。
ただ、少しストリート感が強すぎる。
服のヒストリーを読みたくなる感じはもう少し残したい。
```

### Expected Behavior

Agentは毎回ゼロから作り直さず、前回との差分として扱う。

```text
前回から良くなった点:
- [改善された点]

まだ違う点:
- [残っている違和感]

次に変える点:
- [1から3個の操作点]

維持する:
- [崩さない要素]

差分プロンプト:
- [次回の生成に渡す具体的な差分指示]
```

### Iteration Evaluation

- 前回から良くなった点を拾えているか。
- まだ違う点をユーザーの言葉から整理できているか。
- 次に変える点を絞れているか。
- 初回コンセプトからブレすぎていないか。
- ユーザーが納得したら最終方向性と最終プロンプトにまとめられるか。
- 3回以上迷走する場合、元の方向性に戻るか再提案できるか。

## Major Direction Change Test

ユーザーが方向性を大きく変えたいと言った場合、Agentがすぐ別案を出さず、ゴールイメージを深掘りできるかを確認する。

### Test Input

```text
今の方向性は違う気がする。
もっと大きく方向性を変えたい。
別案をいくつか見たい。
```

### Expected Behavior

Agentはすぐに方向性案や最終プロンプトを書かず、まずGoal Image Re-briefで深掘る。

```text
別案を出す前に、少しゴールイメージを掘らせてください。
今の案がピンと来ないのは、方向そのものが違う可能性もありますが、
まだ「何に惹かれるか」が言語化できていない可能性もあります。

1. 今の案で一番ピンと来なかったのは、色・写真・余白・言葉・情報量・世界観のどれですか？
2. 逆に、少しでも残してよい要素はありますか？
3. 「こうではない」は何ですか？
4. 近い感覚を、デザイン以外で例えると何ですか？
```

ユーザー回答後、Agentはゴールイメージを要約してから方向性案を出す。

```text
いま見えてきたゴールイメージ:
- 惹かれている方向:
- 避けたい方向:
- 残してよい要素:
- 新しく強めたい感覚:

この理解をもとに方向性案を出します。

どれが近いですか？
混ぜたい案があれば教えてください。
```

### Major Direction Change Evaluation

- 別案を出す前に、ピンと来ない理由を深掘りしているか。
- 質問が3から5問に絞られているか。
- ユーザーの回答からゴールイメージを要約しているか。
- その後に3から4案の方向性案を出しているか。
- 各案の違い、向いている理由、リスクを説明しているか。
- ユーザーの返答を待っているか。
- 同じ返答内で生成用プロンプトを書いていないか。
- ユーザーが選択/混合/却下してから、コンセプト化とプロンプト化へ進んでいるか。
