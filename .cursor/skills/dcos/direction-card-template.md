# Direction Template

これはAgent内部で使う方向性案のテンプレート。ユーザーには原則として「Direction Card」と言わず、「方向性案」「候補」として提示する。

方向性案は、ユーザーがデザイン方向性を選び、混ぜ、判断するためのもの。単なるアイデアではなく、根拠、リスク、生成用プロンプトへの渡し方まで含める。

## User-Facing Summary

ユーザーに見せるときは、まず短く出す。

```markdown
## A. [案の名前]
[一言でいうと何か]

- 目指す印象:
- 色や形の方向:
- 向いている理由:
- 注意点:
```

必要になった場合だけ、詳細項目を展開する。

## Internal Template

```markdown
## Direction: [Name]

### User Feeling
[ユーザーに持ってほしい感情]

### Visual Keywords
[視覚方向性を表す短い語句]

### Color
[色の方向性。固有の色コードではなく、色相・明度・彩度・役割で書く]

### Shape
[形、線、面、角丸、図形文法]

### Typography
[文字の印象、見出しと本文の関係]

### UI Parts
[カード、チップ、ナビゲーション、チャット、ステップ、図解など]

### Why This Fits
[事業骨格、体験感情、避けたい既視感に対して合う理由]

### Reference Mix
[複数の参照文脈から、何の考え方・構造・表現原理を借りるか]

### Search Keywords / Verified References
[未確認URLは出さない。検索キーワード、ユーザー提供URL、または確認済みURLだけを書く]

### Do Not Imitate
[ブランド固有表現、レイアウト、色、ロゴ、コピーなど、真似しない点]

### Risks
[軽く見える、冷たく見える、既視感が出るなどのリスク]

### How To Control
[リスクを抑える設計上の制御方法]

### Moodboard Prompt
[ムードボード生成用の短いプロンプト]

### First Visual Prompt
[初回ビジュアル生成用の短いプロンプト]

### UI/LP Generation Prompt Notes
[UIやLPの生成用プロンプトに残す条件]
```

## Rules

- 原則として3案出す。
- 似た案を3つ出さず、明確に違う判断軸を作る。
- 「無難案」「攻め案」「中間案」に固定しない。案件の文脈に合わせる。
- 実在ブランドの模倣を避け、参照文脈として扱う。
- 参照は1つに寄せず、写真、情報設計、タイポグラフィ、UI文法などに分解して混ぜる。
- 未確認URLは断定的に出さない。URLが必要なら、ユーザー提供URLまたは確認済みURLに限る。
- リスクと抑制策を必ず書く。
- 最後に生成用プロンプトへ渡せる制約や優先順位を残す。

## Selection Prompt

方向性案を出した後は、ユーザーにこう聞く。

```text
どれが近いですか？

Aに近い
Bに近い
Cに近い
AとCを混ぜたい
どれも違う

違う場合は、「もっと堅く」「もっと楽しく」「もっと高級感」など感覚語で返して大丈夫です。
```
